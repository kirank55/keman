API keys leak.

Committedto a repo, then “removed” while it stays in history
Printedin a CI log or an error report
Bakedinto a container image or a mobile app
Copiedoff a laptop, a backup or a shared .env

When one does, the provider key works for anyone, from anywhere, until you notice. Keman makes the leaked copy worth much less, and easy to kill.

A leaked key only works where you allow it

Keman sits between your apps and the provider. Apps send a kmn_… virtual key. Keman checks it, then forwards the request with the real key, which never leaves Keman.

Alert

Every alert tells you what to do next

Alerts go to Slack or a signed webhook. Each one says who called and from where, and leads with the exact command to respond: rotate if it wasn’t you, disable if you’re not sure, allow the address if it was.

# security-alertsKeman alerts
KemanAPP4:31 PM
[high] spend_spike on virtual key support-bot (eWjbqwBD) from 203.0.113.200 (BR, AS64510) calling POST /v1/messages evidence: {"hour_microusd":5298533,"model":"claude-opus-4-5","p95_microusd":144411,"threshold_microusd":5000000} what to do: Not you: issue a replacement and revoke the leaked key now keman key rotate eWjbqwBD --grace 0 Not sure: turn it off until you know (reversible) keman key disable eWjbqwBD It was you: allow this address and nothing else keman policy set eWjbqwBD --cidr 203.0.113.200/32 It was you: allow this country and nothing else keman policy set eWjbqwBD --country BR

Contain

Kill a leaked key in one command

keman key rotate issues a replacement with the same policy and revokes the leaked copy. The real provider key stays the same, and so does every other app. Use --grace 24h for a planned rotation.

acme-api
acme-api $ keman key rotate support-bot --grace 0
store the new virtual key (token) now; it is not shown again

Deceive

Plant a decoy, catch the thief

Canary keys look like real ones and never reach the provider. Plant one in a repo, a CI config or a backup. Its first use raises a critical alert, so you know what else was stored next to it.

acme-api
acme-api $ keman canary create --credential openai-main --name decoy --base-url https://keman.example.com >> .env.bak
canary decoy (CgrngVMh) created. Plant the lines above where a thief would look: a .env in a repo,
CI variables, an old config or a backup. Any use raises a critical alert and never reaches the upstream.
Keep the snippet free of comments that mention keman or canaries.
acme-api $ cat .env.bak
OPENAI_API_KEY=kmn_CgrngVMh_3WZbZ3Ndk6MlvxSFyEqersjEhBfwYG4VTSQVwVabp05

Harden

Know which keys would hurt if they leaked

Lock each key to the addresses or countries it runs from, the paths and models it may call, a request rate and a daily dollar cap. New keys expire after 90 days. keman exposure lists the keys that are still easy to abuse, with the fix for each.

acme-api $ keman exposure

Built to be trusted with your keys

Self-hosted

Runs on your machine or your network. No account, no cloud service, and it never phones home.

Real keys stay put

Provider keys are encrypted at rest and never sent to apps. Virtual keys are stored only as hashes.

Your data is not logged

Request bodies, headers and query strings are never logged. For LLM calls Keman reads only the model and token settings, and the usage counts.

Fast

About 0.07 ms added at the median on loopback. Responses stream back unbuffered, including SSE from the official SDKs.

One binary

A single Go binary with pure-Go SQLite, for Linux, macOS and Windows, plus a distroless multi-arch image.

Verifiable

Apache-2.0. Every release ships SHA-256 sums, an SPDX SBOM and a keyless cosign signature.

Install

Then run keman init and keman to open the terminal UI and start the proxy.

$ curl -fsSL https://raw.githubusercontent.com/kirank55/keman/main/scripts/install.sh | sh

Picks the binary for your OS and CPU, checks its SHA-256 sum (and its cosign signature if cosign is installed), and installs to /usr/local/bin or ~/.local/bin. Read the script.

$ go install github.com/kirank55/keman/cmd/keman@latest

Needs Go 1.22 or newer. No CGO.

$ docker volume create keman-data $ docker run --rm -v keman-data:/home/nonroot ghcr.io/kirank55/keman:beta init $ docker run --rm -p 8080:8080 -v keman-data:/home/nonroot ghcr.io/kirank55/keman:beta serve

Multi-arch (amd64, arm64), distroless, non-root, and signed with cosign.

Download keman_<os>_<arch> (.exe on Windows) from GitHub Releases. Every binary has a SHA-256 sum, an SBOM and a cosign signature. How to verify a release.

Questions

Does Keman see my prompts?

It forwards them, the way any proxy does, but it doesn’t keep them. For LLM APIs it reads only model, stream, max_tokens and stream_options from the request, and only the usage counts from the response. Bodies, headers and query strings are never logged. It runs on your own machine, so nothing goes to a third party.

How much latency does it add?

On loopback, about 71 µs at the median and 555 µs at p99 (benchmark). Responses, including streams, are passed back unbuffered.

Which APIs does it work with?

OpenAI-compatible APIs (including OpenRouter), Anthropic, and any HTTP API that authenticates with a header, such as Stripe or GitHub. Spend caps and model allowlists work for OpenAI and Anthropic. Generic APIs get a path allowlist, so a leaked key can only call the endpoints you listed.

Can’t I just use provider-scoped keys or a secret scanner?

Use both if you can. Scanners tell you a key leaked; Keman makes the leaked copy hard to use and gives you one switch to kill it. Provider scoping differs from provider to provider. Keman gives every key the same locks, alerts, decoys and one-step rotation, and adds them to APIs that have none. It also ships a scanner: keman scan . --history.

Do country and network rules need anything extra?

Yes. Country and ASN rules, and country locks, need a GeoLite2 or DB-IP .mmdb file. Keman does not bundle one. Address locks, expiry, caps, decoys and the other rules work without it.

What doesn’t it protect against?

Anyone who can read Keman’s memory or its host can read the real keys. Run it isolated from the apps that use it, and keep the admin listener off the network. The threat model lists the rest.

Is it ready for production?

It’s a beta. It runs as a single instance on SQLite and proxies HTTP only (no WebSockets yet, so no OpenAI Realtime). Please try it and open an issue with anything that gets in your way.

What does it cost?

Nothing. Keman is free and open source under Apache-2.0, and runs on your own hardware.
