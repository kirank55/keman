How it works

A leaked key only works where you allow it

Keman sits between your apps and the provider. Apps send a kmn_… virtual key. Keman checks it, then forwards the request with the real key, which never leaves Keman.

Your app

Holds a virtual key

A leaked copy

Used from a network or country you never allowed

Keman

  • Checks address, country, expiry, paths and models
  • Limits requests per minute and dollars per day
  • Watches for new countries, spikes and decoys
  • Swaps in the real key, encrypted at rest

Deceive

Plant a decoy, catch the thief

Canary keys look like real ones and never reach the provider. Plant one in a repo, a CI config or a backup. Its first use raises a critical alert, so you know what else was stored next to it.

acme-api
acme-api $ keman canary create --credential openai-main --name decoy --base-url https://keman.example.com >> .env.bak
canary decoy (Dh98cXlL) created. Plant the lines above where a thief would look: a .env in a repo,
CI variables, an old config or a backup. Any use raises a critical alert and never reaches the upstream.
Keep the snippet free of comments that mention keman or canaries.
acme-api $ cat .env.bak
OPENAI_API_KEY=kmn_Dh98cXlL_eLGVO5FpIj1FQ3bUnO7qemo9pAhOwvBlAh831fo6MFP

In the box

Everything a key needs to be safe to lose

Address and country locks

Allow CIDRs and countries per key. Everything else is refused.

Expiry by default

New keys expire after 90 days. Set a date, a duration, or never.

Endpoint and model lists

Every preset ships a path allowlist, and a custom API requires one. LLM keys can also be held to a list of models.

Dollar caps and rate limits

Daily and monthly caps on LLM keys, reserved before each request, and requests per minute on any key.

21 platform presets

keman upstream add --preset groq fills in the host, TLS, paths and auth.

Auto-disable, with a dry run

Let spikes and new countries turn a key off, after a 7-day dry run shows what would have tripped.

Planned rotation

Rotate with a 1-hour, 24-hour or 7-day grace period, so both keys work while you deploy.

Swap the real key in place

keman credential rotate changes the provider key. Virtual keys keep working.

Slack and signed webhooks

HMAC-SHA256 signed, with the evidence and the commands to respond.

Terminal UI, CLI and API

Everything the UI does is also a one-shot command for scripts.

Prometheus metrics

Requests, latency, alerts and queue depth on /metrics.

Test your detections

keman detection test replays abuse scenarios, or your own events.

Trust

Built to be trusted with your keys

Self-hosted

Runs on your machine or your network. No account, no cloud service, and it never phones home.

Real keys stay put

Provider keys are encrypted at rest with AES-256-GCM and never sent to apps. Virtual keys are stored only as hashes.

Your data is not logged

Request bodies, headers and query strings are never logged. For LLM calls, Keman reads only the model and token settings, and the usage counts.

Fast

About 0.07 ms added at the median on loopback. Responses stream back unbuffered, including SSE from the official SDKs.

One binary

A single Go binary with pure-Go SQLite for Linux, macOS and Windows, plus a distroless multi-arch image.

Verifiable

Apache-2.0. Every release ships SHA-256 sums, an SPDX SBOM and a keyless cosign signature.

Get started

Up and running in a few minutes

  1. 1

    Install

    One static binary. No runtime, no CGO.

    $ curl -fsSL https://raw.githubusercontent.com/kirank55/keman/main/scripts/install.sh | sh

    Picks the binary for your OS and CPU, checks its SHA-256 sum (and its cosign signature if cosign is installed), and installs to /usr/local/bin or ~/.local/bin. Read the script.

    $ go install github.com/kirank55/keman/cmd/keman@latest

    Needs Go 1.22 or newer.

    $ docker volume create keman-data $ docker run --rm -v keman-data:/home/nonroot ghcr.io/kirank55/keman:beta init $ docker run --rm -p 8080:8080 -v keman-data:/home/nonroot ghcr.io/kirank55/keman:beta serve

    Multi-arch (amd64, arm64), distroless, non-root, and signed with cosign.

    Download keman_<os>_<arch> (.exe on Windows) from GitHub Releases. Every binary has a SHA-256 sum, an SBOM and a cosign signature. How to verify a release.

  2. 2

    Start it

    init prints the admin token once. keman opens the terminal UI and starts the proxy. Press a, pick your platform, and paste its key. The form for your first virtual key opens next.

    $ keman init # writes keman.yaml and master.key, prints the admin token $ keman # opens the terminal UI and starts the proxy

    Prefer scripts? Every step is a command too: keman upstream add --preset openai, keman credential add --upstream openai --name primary --secret-env OPENAI_API_KEY, keman key create --credential primary --name laptop.

FAQ

Questions

Does Keman see my prompts?

It forwards them, the way any proxy does, but it doesn’t keep them. For LLM APIs it reads only model, stream, max_tokens and stream_options from the request, and only the usage counts from the response. Bodies, headers and query strings are never logged. It runs on your own machine, so nothing goes to a third party.

How much latency does it add?

On loopback, about 71 µs at the median and 555 µs at p99 (benchmark). Responses, including streams, are passed back unbuffered.

Which APIs does it work with?

Keman ships presets for 21 platforms: OpenAI, Anthropic, OpenRouter, Gemini, Groq, Mistral, DeepSeek, xAI, Together AI, Fireworks AI, Cerebras, Stripe, GitHub, Slack, Twilio, SendGrid, Resend, Postmark, Cloudflare, Linear and Notion. Any other HTTP API that takes a key in a header or HTTP Basic works too. LLM platforms get spend tracking, dollar caps and model allowlists. Every platform gets a path allowlist, so a leaked key can only call the endpoints you allow.

Can’t I just use provider-scoped keys or a secret scanner?

Use both if you can. Scanners tell you a key leaked. Keman makes the leaked copy hard to use and gives you one command to kill it. Provider scoping differs from provider to provider. Keman gives every key the same locks, alerts, decoys and one-step rotation, including on APIs that have none. It also ships a scanner: keman scan . --history.

Isn’t Keman a single point of compromise?

It holds the real keys, so it’s the thing to protect. That trade is deliberate: one hardened place instead of a real key in every app, CI job and laptop. Run it isolated from the apps that use it, and keep the admin listener off the network. It does not protect you if someone can read its memory. The threat model covers the rest.

Do country and network rules need anything extra?

Yes. Country and ASN rules, and country locks, need a GeoLite2 or DB-IP .mmdb file. Keman does not bundle one. Address locks, expiry, caps, decoys and the other rules work without it.

Will normal traffic set off alerts?

A new key learns for 7 days or 500 requests before the spike and new-location rules alert. Decoys, disabled keys and repeated refusals alert from the first request. keman detection test shows what would fire before it matters.

Is it ready for production?

It’s a beta. It runs as a single instance on SQLite and proxies HTTP only (no WebSockets yet, so no OpenAI Realtime). Please try it and open an issue for anything that gets in your way.

What does it cost?

Nothing. Keman is free and open source under Apache-2.0, and runs on your own hardware.
